# Quarterdeck 4.0.0

Quarterdeck runs a crew of coding agents from one board on your own machine. You describe the work to a Planner and approve the tickets it proposes; a Driver hands them to builders, each in its own git worktree, and a reviewer reads every pull or merge request before Quarterdeck merges it. It works through the agent CLIs you already use (Claude Code, Kiro, Gemini CLI), stops for you with a card whenever an agent wants something your rules do not allow, and keeps everything it stores in one folder you can delete.

## Get it running

With Node 22, git and one agent CLI installed:

```sh
git clone https://github.com/<owner>/quarterdeck.git && cd quarterdeck
npm install
npm run quarterdeck -- up
```

`<owner>` is the account this release is under; copy the clone URL from the repository page. Open the URL `up` prints. The first time, it opens on Setup. **`docs/team-quickstart.md`** in the repository walks you from here to a first voyage, with one track for Claude Code (subscription or Vertex AI) and one for Kiro on GitLab.

Quarterdeck is not on npm. The `quarterdeck` package there is someone else's: do not install it, and do not run `npx quarterdeck`.

## What changed since October 3

- **Setup screen.** `up` with nothing configured opens the dashboard on Setup: pick a folder, a runtime and a rules profile, sign in, and land on the board with the Planner ready and a short "What to do first" panel. `init` and `doctor` still do the same from a terminal, through the same code.
- **Sign in through the runtime itself.** A signed-out Claude Code, Kiro, Gemini CLI, gh or glab is signed in with its own browser sign-in, from `doctor`, `up`, `init`, Setup or a dashboard card. A card with a command to copy is now only the fallback. Quarterdeck never sees the token.
- **Workspaces and single-repo mode.** You point Quarterdeck at one folder, once. A single repository gets a single-repository tool: no project picker, no project column, no cross-project wording. A folder of repositories makes each one a project, and one voyage can span them. The workspace lives in `~/.quarterdeck/workspace.json`.
- **Claude on Vertex AI.** The Claude Code runtime has three auth modes per machine: `subscription` (the default), `vertex` (`QUARTERDECK_CLAUDE_AUTH=vertex` with `ANTHROPIC_VERTEX_PROJECT_ID`, `CLOUD_ML_REGION` and gcloud's application-default credentials) and `api_key` (the key from `ANTHROPIC_API_KEY` or the macOS Keychain, handed to the agents and never stored). `doctor` reports the mode and anything it is missing.
- **Rules profiles.** What agents are told about your coding standard is now a profile you choose. The shipped `default` is generic and language-neutral; your team's profile lives on your machine and points at your own standards docs, rule levels and reviewer checks. Pick it in Setup, in the Rules widget or with `profile use`. See `docs/rules-profiles.md`.
- **Keep-awake.** A control in the dashboard header keeps your computer awake (not the screen) while agents work and you are away: for 30 minutes up to 8 hours, or until the voyage ends. It uses `caffeinate` on macOS, `SetThreadExecutionState` on Windows and `systemd-inhibit` on Linux, and lets go when its time runs out, when you turn it off, or when the server stops, even if it is killed. The screen can still turn off and lock, and on a laptop on battery, closing the lid still sleeps. `doctor` says whether this machine supports it.
- **Images in the Planner and in card answers.** Paste a screenshot, drop a file or pick one with the attach button: PNG, JPEG, GIF or WebP, up to 5 images of 5 MB each per message, and a message can be images only. Agents get them as images when their runtime takes images in a prompt (Claude Code, Kiro and Gemini CLI all do today), and as file paths otherwise. Images are saved under `~/.quarterdeck/<project>/attachments/`, never in the database, and show again in the transcript after a reload.
- **The chat input is a regular chatbox.** Enter sends; Shift+Enter adds a line and continues a list (`1.`, `-`, `- [ ]`), Tab and Shift+Tab indent list items, and the box grows with what you type up to a limit. A paste always lands as plain text, and undo works on lists and pastes too.
- **Version 4.0.0** everywhere, set by `node scripts/version.mjs <version>`, and a CI job that proves a clean Node 22 container can clone, install, start, run Setup and complete one voyage on a fake runtime.

## Known limits

- Alpha. Run it on repositories and branches where a bad merge is cheap to undo. Merges wait for your answer on a card unless you turn `autoMerge` on.
- One machine, one person. There is no shared server and no multi-user mode.
- Setup has no folder picker: browsers do not give a page a folder's path, so you type or paste it.
- Setup saves a non-default runtime for the whole machine. A per-repository runtime is still `init --folder` in a terminal.
- `up` prints the URL; it does not open the browser.
- Self-hosted GitLab needs one line in `~/.quarterdeck/rules.local.forges.json` before Setup, and GitLab has no AI reviewer by default.
- The Claude agent is fetched through `npx` at a pinned version, but its dependencies are not locked, so two machines can run slightly different code under it.
- Kiro's in-protocol sign-in is not documented to open a browser; when it does not, Quarterdeck runs `kiro-cli login`, which does.
- Quarterdeck never publishes packages. When a library ticket merges, the Driver publishes it with the project's own tooling.

## Where your data lives, and how to delete it

Everything Quarterdeck stores is on your machine, in `~/.quarterdeck/`: each project's database, every agent turn, builder worktrees, the images you attach (`~/.quarterdeck/<project>/attachments/`), your rules and your workspace. While keep-awake is on, `~/.quarterdeck/keep-awake.json` records which process holds it. Nothing is sent anywhere: no account, no hosted service, no telemetry. Quarterdeck holds no API keys; your runtimes, gh and glab keep their own sign-ins. The dashboard listens on `127.0.0.1` with a new token on every start, and anything shaped like a secret is stored as `[redacted]`.

- **One project:** the Data widget's **Wipe project**, or `npm run quarterdeck -- wipe <project>`. This deletes its database, turns, worktrees and attachments.
- **Every project:** **Wipe everything**, or `npm run quarterdeck -- wipe --all`. Your rules files stay.
- **All of it:** stop `up`, delete `~/.quarterdeck/`, and run `git worktree prune` in each repository you used.

Outside that folder, Quarterdeck writes `<repo>/.quarterdeck/` only when you agree to it, and Kiro's per-agent config in `~/.kiro/agents/quarterdeck-*.json`, removed when the agent stops.
