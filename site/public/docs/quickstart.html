Quickstart

Pick one agent runtime, sign in to it and to your forge (GitHub or GitLab), point Quarterdeck at a git repository, and start it. Kiro is the default; Claude Code and Gemini CLI work the same way.

You need Node.js 22 or later and a git repository whose remote is on GitHub or on GitLab (gitlab.com or your own instance). Quarterdeck never signs in for you and never asks for an API key: each runtime signs in through its own CLI, and npm run quarterdeck -- doctor tells you exactly which command to run.

Running it

Quarterdeck is installed and run locally only: clone it, install it, and run it on your own machine. It is not published to npm. The quarterdeck package on npm is someone else's, unrelated to this one: do not install it, and do not run Quarterdeck through npx, which would download and run that package instead. 

git clone https://github.com/<owner>/quarterdeck.git
cd quarterdeck
npm install
npm run quarterdeck -- up

npm install installs the dependencies and builds every package; run it again after a git pull. Then open the dashboard at the URL up prints. Every command on this page runs from the clone the same way, as npm run quarterdeck -- <command>.

1. See what is missing

npm run quarterdeck -- doctor

Doctor checks kiro-cli, claude, gemini and gh: installed, which version, and signed in. Every miss is followed by the command that fixes it. You only need the runtime you pick and gh; the other runtimes can stay on the list. When a GitLab host is in use it checks glab too (see GitLab). Doctor exits 0 when everything is ready and 1 otherwise. It never signs in for you and never starts a download.

2a. Kiro

Kiro is the runtime Quarterdeck uses out of the box. Doctor prints:

kiro-cli: not installed
  Install: curl -fsSL https://cli.kiro.dev/install | bash
  Sign in: kiro-cli login

Run the two commands. Once kiro-cli whoami succeeds, doctor shows kiro-cli: <version>, signed in.

2b. Claude Code

Quarterdeck runs Claude Code through a pinned @agentclientprotocol/claude-agent-acp package with npx, so you do not need a separate claude install. Doctor prints: 

claude: @agentclientprotocol/claude-agent-acp@0.85.0 is not downloaded yet
  Download: npx --yes @agentclientprotocol/claude-agent-acp@0.85.0 --cli --version
  Sign in: npx --yes @agentclientprotocol/claude-agent-acp@0.85.0 --cli auth login --claudeai

The download is about 240 MB, which is why doctor leaves it to you. The sign-in uses your claude.ai account. An API key or a non-Anthropic backend that Claude Code is already set up for counts as signed in too.

2c. Gemini CLI

Doctor prints:

gemini: not installed
  Install: npm install -g @google/gemini-cli
  Sign in: gemini, then choose Login with Google (or set GEMINI_API_KEY)

Doctor counts Gemini as signed in when GEMINI_API_KEY is set, when GOOGLE_GENAI_USE_VERTEXAI=true is set with GOOGLE_API_KEY or GOOGLE_CLOUD_PROJECT, or when ~/.gemini/oauth_creds.json exists after a Google login.

3. GitHub

Builders open pull requests and the merge gate merges them with gh. Install it (brew install gh on macOS, winget install --id GitHub.cli on Windows, or your system's package), then sign in: 

gh: 2.81.0, not signed in
  Sign in: gh auth login

Run npm run quarterdeck -- doctor again until your runtime and gh say signed in.

GitLab

On GitLab, builders open merge requests and the merge gate merges them with glab, and everything Quarterdeck says to agents and shows you says merge request (MR) instead of pull request (PR). A repository on gitlab.com needs nothing more. For a self-hosted GitLab, map its host once in ~/.quarterdeck/rules.local.forges.json (see forges.json): 

{ "forges": { "git.example.org": "gitlab" } }

Doctor then checks glab for every GitLab host it knows about, and for the repository it runs in: 

glab: not installed, needed for git.example.org
  Install: brew install glab
  Sign in: glab auth login --hostname git.example.org

4. Create a project

npm run quarterdeck -- init /path/to/your/repo

init creates ~/.quarterdeck/ and a project for the repository (the current directory if you leave the path out). In a terminal it asks for the runtime: 

Runtime (kiro, claude, gemini) [kiro]:
  • Kiro: press Enter. Nothing else is written.
  • Claude Code: type claude, or pass --runtime claude.
  • Gemini: type gemini, or pass --runtime gemini.

A runtime other than the machine's default has to be saved somewhere, so init asks where: in a .quarterdeck/ folder in the repository, for this project only (--folder), or in ~/.quarterdeck/, for every project on this machine (--no-folder). That folder is the only thing init ever writes into your repository, and only after you say yes. Without a terminal, pass --runtime and one of the two flags. 

Created project my-app (my-app) for /home/you/code/my-app
Runtime: kiro
Data: /home/you/.quarterdeck/my-app
Next: npm run quarterdeck -- up

The project slug comes from the folder name; --project and --name set the slug and display name yourself. If init fails or you cancel it, nothing is left behind. Run init once for each repository you want worked: one server and one voyage cover them all.

5. Start Quarterdeck

npm run quarterdeck -- up
Quarterdeck is running at http://127.0.0.1:4317
Data: /home/you/.quarterdeck
Press Ctrl+C to stop.

Open the URL. One process serves the dashboard and the API on 127.0.0.1 only. --port picks another port (0 picks a free one); a port that is already taken is an error that says so. Ctrl+C stops the server and closes every project.
