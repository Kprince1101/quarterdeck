FAQ

Do I need an API key or an account?

No. Quarterdeck has no account and asks for no key. Each runtime signs in through its own CLI with whatever you already use, and npm run quarterdeck -- doctor prints the command for each. See the quickstart.

Does Quarterdeck send anything anywhere?

No. There is no hosted component and no telemetry, and the server listens on 127.0.0.1 only. The agents themselves talk to their own providers, as they do when you run them by hand, pull requests go to GitHub through gh, and merge requests go to GitLab through glab. A tracker is reached only by the agents, with the CLI or MCP server you name; Quarterdeck never calls it.

Does it work with GitLab?

Yes, gitlab.com and self-hosted instances. A self-hosted host needs one line in forges.json; after that, agents and the dashboard say merge request instead of pull request, and npm run quarterdeck -- doctor checks glab. See GitLab.

Can it work across several repositories?

Yes. Add each repository as a project; one voyage, one Driver and one reviewer then work them all. Tickets can depend on tickets in other projects, and a library can be marked as publishing, so the apps that use it wait for its release, not just its merge. See how Quarterdeck fits a multi-repo effort.

Can agents use my ticket tracker?

Yes. Name the tracker and how to reach it (a CLI command or an MCP server) in the Project widget or in services.json. Every agent working a ticket is told, along with the ticket's id there. See project services.

Which runtime should I use?

Kiro is the default. Claude Code and Gemini CLI work too, and you can mix them: models.json sets the runtime for each role, so the reviewer can run on a different runtime from the builders. On Kiro, each role can start from one of your own Kiro agents; see kiro.json.

What happens when a sign-in expires?

You get a card with the exact command to run. Quarterdeck waits for you and then tries again. It never signs in for you.

Will it merge pull requests on its own?

Not unless you turn that on. By default a pull request needs the reviewer's approval and passing checks, and then you get a merge card; nothing merges until you answer it. Setting autoMerge to true on your machine lets the gate merge by itself, and a repository can never turn that on for you. You can also make it wait for an AI review with requireAiReview.

Can an agent run any command it likes?

No. Every permission request is answered from permissions.json. Out of the box, agents may read, search and think inside the repository, and everything else asks you with a card. No rule can let an agent write outside the repository.

What does Quarterdeck write into my repository?

Nothing, unless you agree to a .quarterdeck/ folder for that project's rules. Builders work in their own git worktrees under ~/.quarterdeck/ and change your code only through pull requests (merge requests on GitLab).

Can I use my own Postgres?

Yes. Set DATABASE_URL and every project is stored in that database. See your own Postgres.

How do I delete everything?

Stop Quarterdeck and delete ~/.quarterdeck/. Then run git worktree prune in each repository you used. See deleting it.

Port 4317 is taken. What now?

Another Quarterdeck may already be running. Otherwise start it on another port with npm run quarterdeck -- up --port 5000, or --port 0 to pick a free one.
