Widgets

The dashboard is made of widgets that you arrange on a grid. Layouts are JSON the server keeps, and presets ship with Quarterdeck: the first is Board, then the Planner, Driver and Notebook as tabs, then Events and the pull and merge requests.

The dashboard is still being built, so this page says what each widget is for, not what it looks like. Every widget shows state the server streams to it; anything you do in one is sent to the server, which is the only thing that changes state. The widgets are listed in the order the grid's tray lists them.

Agents

The crew: the Planner, the Driver, the reviewer and the builders. Each agent shows its state and how long it has been in it, the ticket it is working on and the other open tickets it has (a killed agent's tickets show as blocked), and any work a pause is holding for it, such as held: continue: fix lint (agent), until that work is replayed or dropped.

A live agent offers Pause (or Resume), Poke, Kill, Retire and Reset; an ended or killed one offers Retire and Reset. After Kill the agent shows killing… until the server confirms it was killed or says why it could not be. Poke is sent as a message to the agent, which the server does not deliver yet.

Board

The voyage, and whether everything is alive. One voyage runs at a time, across every project: start it with a goal, end it, or Kill all, which reopens its tickets. Each project in the voyage has its own Kill, which stops that project's builders and leaves the voyage running. Below it the Board shows the stream's status, then each picked project with its live agents, tagged voyage, paused or archived. Pause all stops new work in every project and the Board then says Paused everywhere; Resume all undoes it. Up to four projects are shown at once: the first four by name until you pick, and archived projects only when Show archived is on.

Cards

Decisions waiting for you: permission requests, questions from agents, merges, sign-ins. A declined or unanswered card is a result the agent sees, not a crash.

Data

Every table Quarterdeck keeps for the project with its row count, and its rows a page at a time, newest first. Below them, every path on disk the project uses and whether it exists yet, with a Wipe button for one project and one for everything. Each asks you to type the project's name, or wipe everything, and stops the agents before it deletes anything. See where your data lives.

Driver

The turns of the voyage's Driver, the one coordinator for every project: what it was told, what it answered and the actions it took, such as assigning a ticket, blocking one on another project's work, or recording that a library was published. Pick an earlier voyage to read its turns. Each turn shows the command that replays the Driver up to it in a fresh session that writes nothing.

Events

Everything that happened, in order, as it happens, filtered by project and kind. A ticket waiting on another project's work says what it is waiting for (merged but not published yet, for example), and the feed shows when a blocked builder is woken.

Notebook

What earlier Drivers learned, about one project or about every project. Each new Driver is born with the entries of every project in its voyage.

Planner

Your conversation with the Planner, which turns what you describe into tickets for you to approve. One conversation plans for every active project: each proposal shows the project it belongs to, and editing it can move it to another project. Each proposal is a spec, shown and edited section by section: Requirements, Design, Tasks and the Proven line.

Project

One project: pause it, turn the AI review gate and auto-merge on or off for your machine, see the reviewer and how many agents have retired, and archive it. Its services are here too: the forge detected from its remote, its tracker and how agents reach it, and whether it publishes. See project services.

Pull and merge requests

The open pull requests (GitHub) or merge requests (GitLab) of every active project, each with its branch and base, draft flag, checks or pipeline, review state, age, a link to open it on the forge, and the ticket and agent it belongs to when Quarterdeck knows them. Headings and empty states use each project's own terms; a forge that cannot be read shows its error in that project's section only.

Rules

The rules files, edited in place. Edits are saved as rules.local.* files and checked before they are written. While you edit permissions, every broad shell allow gets a one-line warning saying what it permits.

Tables

How many rows of each table the stream holds right now. It is the smallest widget, and the one to copy when you write your own.

Usage

Tokens this project's agents spent in the budget window, the same count that holds launches. If budget.window sets a capTokens, it shows the share of that cap, amber from 60% and red from 80%; otherwise it says no cap is set.
